## 1. Назначение

"Тектоник" - одноместный гусеничный транспорт с вращающимся буром. Он
перемещается по поверхности земли и может прокладывать короткие тоннели под
землёй. Бур является частью ходового механизма, поэтому аппарат расходует
больше энергии в тоннеле, чем на поверхности.

## 2. Стихия и конструкционный элемент

**Стихия:** земля.

**Конструкционный элемент:** передний вращающийся бур, описанный публичным
атрибутом `drill_diameter_m`. Бур позволяет "Тектонику" перемещаться в режиме
`tunnel` и определяет, какие препятствия он способен преодолеть.

Ограничения стихии:

- Основной режим - движение по поверхности (`ground`).
- Дополнительный режим - прокладка тоннеля (`tunnel`).
- Транспорт не летает и не умеет перемещаться по воде.
- Положение измеряется пройденным расстоянием по маршруту, без координат и
  направления.

### 3.4. Методы

#### 3.4.1. `move`

```python
def move(self, distance_km: float, terrain: str) -> float:
    ...
```

Перемещает транспорт на положительное расстояние по выбранной среде и
возвращает время перемещения в часах.

Допустимые значения `terrain`: `"ground"`, `"tunnel"`, `"water"`.

Числовой аргумент `distance_km` подчиняется общему правилу числовых входов из
раздела 3.2. Значения `NaN` и бесконечности дают `ValueError`, `bool` и другие
нечисловые типы дают `TypeError`.

Правила:

- для `ground` скорость равна `max_speed_kmh`, расход - `distance_km * 1`;
- для `tunnel` скорость равна `max_speed_kmh * 0.6`, расход -
  `distance_km * 3`;
- после успешного перемещения `position_km` увеличивается на `distance_km`;
- после успешного перемещения энергия уменьшается на рассчитанный расход;
- для `ground` атрибут `is_drilling` становится `False`, для `tunnel` -
  `True`;
- энергия может стать ровно `0`, но не может стать отрицательной;
- состояние изменяется только после успешной проверки всех условий.

Исключения:

- `TypeError` - неправильный тип `distance_km` или `terrain`;
- `ValueError` - `distance_km <= 0` или неизвестный `terrain`;
- `MoleCannotSwim` - `terrain == "water"`; состояние не меняется;
- `MoleNoEnergy` - текущей энергии недостаточно; состояние не меняется.

#### 3.4.2. `can_overcome`

```python
def can_overcome(self, obstacle: str) -> bool:
    ...
```

Проверяет возможность преодолеть препятствие без изменения состояния.

Допустимые значения `obstacle`: `"boulder"`, `"landslide"`, `"ravine"`.

Правила:

- `boulder` - `True`, если `drill_diameter_m >= 1.0`;
- `landslide` - `True`, если `energy >= 30.0`;
- `ravine` - `True`, если `drill_diameter_m >= 2.0`;
- во всех остальных допустимых случаях возвращается `False`.

`TypeError` поднимается для аргумента нестрокового типа, `ValueError` - для
неизвестного препятствия. Состояние не изменяется.

#### 3.4.3. `calculate_energy`

```python
def calculate_energy(self, distance_km: float, terrain: str) -> float:
    ...
```

Рассчитывает расход энергии по тем же формулам, что и `move`, но не изменяет
ни один атрибут и не проверяет текущий запас энергии. Для `ground` возвращается
`distance_km * 1`, для `tunnel` - `distance_km * 3`.

Проверки типов и расстояния совпадают с `move`, включая общее правило
числовых входов. Для неизвестного `terrain` поднимается `ValueError`, для
`"water"` - `MoleCannotSwim`. Нехватка текущей энергии на результат не влияет.

#### 3.4.4. `refuel`

```python
def refuel(self, amount: float) -> None:
    ...
```

Пополняет запас энергии на положительное `amount`. Аргумент `amount` принимает
встроенные `int` и `float`, кроме `bool`; значения `NaN` и бесконечности дают
`ValueError`, другие типы - `TypeError`. Итоговое значение не может превысить
`100.0`. Метод не изменяет `position_km` и `is_drilling`.

`TypeError` поднимается для аргумента неправильного типа, `ValueError` - если
`amount <= 0`.

#### 3.4.5. `get_status`

```python
def get_status(self) -> dict:
    ...
```

Возвращает снимок текущего состояния. Словарь содержит ровно следующие ключи:

- `"name"` - `str`;
- `"energy"` - `float`;
- `"position_km"` - `float`;
- `"is_drilling"` - `bool`;
- `"drill_diameter_m"` - `float`.

Изменение возвращённого словаря не изменяет объект транспорта.

## 4. Сценарии

### 4.1. Модульные сценарии

#### Сценарий 1. Обычная поездка по поверхности

**Дано:** "Тектоник" с `max_speed_kmh = 50` и `energy = 100`.

**Когда:** вызвано `move(20, "ground")`.

**Тогда:**

- возвращается `0.4` часа;
- `position_km == 20`;
- `energy == 80`;
- `is_drilling is False`.

#### Сценарий 2. Прокладка тоннеля

**Дано:** "Тектоник" с `max_speed_kmh = 40` и `energy = 50`.

**Когда:** вызвано `move(10, "tunnel")`.

**Тогда:**

- возвращается `10 / 24` часа;
- `position_km == 10`;
- `energy == 20`;
- `is_drilling is True`.

#### Сценарий 3. Нехватка энергии

**Дано:** "Тектоник" с `energy = 10`.

**Когда:** вызвано `move(5, "tunnel")`.

**Тогда:** поднимается `MoleNoEnergy`, потому что требуется `15` единиц.
Позиция, энергия и режим бурения не меняются.

#### Сценарий 4. Бур и препятствия

**Дано:** транспорт с диаметром бура `2.0` м и энергией `40`.

**Когда:** вызваны `can_overcome("boulder")`,
`can_overcome("landslide")` и `can_overcome("ravine")`.

**Тогда:** каждый вызов возвращает `True`, а состояние транспорта остаётся
прежним.

### 4.2. Функциональные сценарии

#### 4.2.1. Под железной дорогой

**Given:** пилот управляет "Тектоником" с диаметром бура `2.0` м, скоростью
`50` км/ч и энергией `70`.

**When:** пилот едет `10` км по поверхности.

**Then:** позиция равна `10` км, энергия равна `60`, транспорт не бурит.

**When:** пилот прокладывает тоннель длиной `6` км.

**Then:** время равно `6 / 30` часа, позиция равна `16` км, энергия равна
`42`, `is_drilling == True`.

**When:** пилот заправляет транспорт на `50` единиц, а затем едет ещё `4` км
по поверхности.

**Then:** энергия равна `88`, позиция равна `20` км, `is_drilling == False`.

#### 4.2.2. Уход от оползня

**Given:** пилот управляет "Тектоником" с диаметром бура `1.2` м,
максимальной скоростью `40` км/ч и энергией `25`.

**When:** пилот проверяет валун и овраг.

**Then:** валун преодолим, овраг непреодолим.

**When:** пилот заправляет транспорт на `10` единиц и проверяет оползень.

**Then:** оползень преодолим, потому что энергия равна `35`.

**When:** пилот едет `5` км по поверхности, а затем бурит `5` км.

**Then:** позиция равна `10` км, энергия равна `15`, время бурения равно
`5 / 24` часа.

#### 4.2.3. Аварийный энергетический резерв

**Given:** "Тектоник" находится в начале маршрута, его энергия равна `20`.

**When:** пилот бурит `6` км.

**Then:** позиция равна `6` км, энергия равна `2`, транспорт бурит.

**When:** пилот пытается бурить ещё `1` км.

**Then:** поднимается `MoleNoEnergy`, позиция и энергия остаются равны `6` км
и `2`.

**When:** пилот заправляет `10` единиц и едет `2` км по поверхности.

**Then:** позиция равна `8` км, энергия равна `10`, транспорт не бурит.

#### 4.2.4. Вода на маршруте

**Given:** "Тектоник" с энергией `50` уже проехал `10` км по поверхности.

**When:** пилот пытается переместиться на `3` км по воде.

**Then:** поднимается `MoleCannotSwim`; позиция равна `10` км, энергия равна
`40`, режим бурения не меняется.

**When:** пилот едет ещё `5` км по поверхности.

**Then:** позиция равна `15` км, энергия равна `35`.

## 5. Граничные случаи

Следующие случаи являются обязательными и проверяются тестами:

- `move(0, "ground")` поднимает `ValueError`;
- `move(1, "ground")` при `energy = 0` поднимает `MoleNoEnergy`;
- `refuel(1000)` при `energy = 50` устанавливает энергию ровно в `100`;
- `move(50, "ground")` при `energy = 50` успешно оставляет энергию равной
  `0`;
- неуспешное перемещение не изменяет ни позицию, ни энергию, ни режим бурения.

### 6.2. Таблица

| Ситуация | Исключение | Сообщение |
| --- | --- | --- |
| Неверный тип аргумента | `TypeError` | не фиксируется |
| Пустое имя или значение вне диапазона | `ValueError` | не фиксируется |
| Неизвестная среда или препятствие | `ValueError` | не фиксируется |
| Недостаточно энергии для перемещения | `MoleNoEnergy` | `not enough energy: required X, have Y` |
| Попытка движения по воде | `MoleCannotSwim` | `tectonic mole cannot move through water` |

Доменная ошибка всегда наследуется от `CrazyVehicleError`, но не обязана
наследоваться от `RuntimeError`.

## 7. Что вне рамок

- Нет моделирования координат, направления и разворота.
- Нет пассажиров, грузов и взаимодействия с другими транспортами.
- Нет реального расчёта физики грунта, прочности тоннеля и разрушения бура.
- Нет графики, анимации и визуализации.
- Нет сохранения состояния между запусками.
- Нет обработки внешних файлов, базы данных, сети и API.
- Нет автоматического ремонта и случайных поломок.
- Тесты не требуют реализации класса до этапа разработки ролью D.

## 9. Открытые вопросы

- Считается ли пройденным расстояние в тоннеле, если тоннель впоследствии
  обрушился? В версии 0.1 учитывается сразу после успешного `move`.
- Нужно ли в будущей версии учитывать разный расход энергии для типов грунта?
  В версии 0.1 среда ограничена двумя режимами без подтипов.
- Должен ли транспорт автоматически выключать режим бурения после остановки?
  В версии 0.1 режим меняется только успешным вызовом `move`.
